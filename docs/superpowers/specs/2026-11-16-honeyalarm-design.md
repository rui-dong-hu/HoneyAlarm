# HoneyAlarm 设计文档

日期：2026-11-16
状态：待用户确认

## 意图与背景（Intent & Why）

孩子的爸爸（用户本人）发现 iPhone 系统闹铃刺耳、突兀，不适合用于叫醒小朋友。希望有一个更柔和、更有人情味的叫醒方式：用一段精心挑选的轻柔音乐作为闹铃，并且可以**混入妈妈（或家人）提前录好的叫醒话语**——比如"宝贝起床啦，妈妈在这等你哦"。

产品是一个**完全离线**、装在用户自己 iPhone/iPad 上的闹钟 App。先给自己家人用，未来可能考虑发布。

## 目标（Goals）

- 在 iPhone 与 iPad 上稳定运行的原生 App。
- 提供两个核心功能：**闹钟** 与 **定时器**。
- 预置若干精心挑选的音乐片段作为铃声（App 内置、免版权）。
- 铃声来源支持四种：① App 内置音乐；② 用户本地录音（如妈妈叫醒话语）；③ 从"文件"App 导入的本地音乐文件（m4a/mp3/wav）；④ 以上任意**混合**结果。
- 所有铃声素材（内置音乐、导入的本地文件、录音）**限制在 1 分钟以内**，保证文件不大、混音轻量；做成的铃声**循环播放**。
- 混合产物**默认保存在本地**；闹钟/定时器设置时**关联一条音乐/铃声**。
- 完全离线运行，不依赖网络、服务器或账号。

## 非目标（Non-Goals）

- v1 不做 App Store 发布、不做推送/远程同步。
- v1 不做混音的高级时间轴编辑（见下"范围"）。
- v1 不支持在 App 内直接播放 / 管理用户 iTunes 音乐库（规避版权与授权复杂化）。
- 不做跨设备账号体系。

## 反目标（Anti-Goals，做了也等于失败）

- 闹钟到了时间却不能可靠响铃（离线闹钟的核心是"准点必响"）。
- 依赖网络才能响铃或播放铃声。
- 录音混音操作过于复杂，家长日常设置时搞不定。

## 约束（Constraints）

- 开发机：Intel Mac（i7-8750H），macOS 15.8.3，16GB RAM。
- 因是 Intel Mac，**Xcode 上限为 16.2**（iOS 18.2 SDK）。不支持 Xcode 17+。
- 用户用**免费 Apple ID** 签名安装到真机，**证书 7 天过期**，需定期重装。
- 目标系统：iOS 15+（同时覆盖 iPhone / iPad）。

## 技术方案（Approaches）

### 方案 A：原生 SwiftUI（采用）
- Swift + SwiftUI，`UNUserNotificationCenter` 做系统级通知闹钟（锁屏、后台也能响），本地音乐用 App 沙盒内置文件 + `AVAudioPlayer` 播放，录音用 `AVAudioRecorder`，混音用 `AVAudioEngine` 实时混合并导出铃声文件。
- **取舍**：开发较重（需 Xcode + 签名），但闹钟的"准点可靠响铃"只有原生通知系统能保证，完全符合"离线可靠"的核心诉求。
- 作为 iPhone/iPad 通用 App（Universal）一个 target 即可。

### 方案 B：PWA / 网页 App（不采用）
- 不装 Xcode、免签名、Mac 上即改即看。
- **致命缺陷**：Web 无法做系统级后台闹钟——无法在锁屏 / 后台准点响铃，违背闹钟 App 核心需求；音乐访问、录音也受限。排除。

### 选择理由
选 A。核心诉求"准点可靠响铃 + 离线 + 混音录音"只有原生通知与原生音频 API 能满足。

## 范围与 v1 定义（Scope）

采用"轻方案"作为 v1：

- 铃声编辑页：选一段**预置音乐**或**从文件 App 导入的本地音乐文件** → **录一段人声** → 调节**人声音量**与**音乐音量** → 试听 → 保存为一条自定义铃声。
- 混音实现：将人声/录音叠在所选音乐之上，混成单一铃声文件（默认保存在本地）。
- 素材长度限制：内置音乐、导入文件、录音均 ≤ 1 分钟，做成铃声后循环播放。
- 预置音乐：App 内置 3–5 段免版权柔和音乐片段。
- 本地文件导入：用系统"文件"App 的文档选择器（`UIDocumentPicker`）导入 m4a/mp3/wav，复制进 App 沙盒。

**v2 候选（本次不做）**：人声在音乐中延后几秒进入、铃声时长剪辑、更多混音参数、多段预置音乐主题包。

## 产品结构（Parts of the How）

### 信息架构
- **底部 Tab**：
  - 闹钟（Alarms）— 列表 + 新建/编辑；每条：时间、重复日、标签、铃声、开关。
  - 定时器（Timer）— 一个主计时器：设定时长、开始/暂停/复位、到时响铃。
  - 设置 / 铃声库（Ringtones）— 预置音乐、录音与混音入口、我的铃声列表。
- 目标：iPhone 单列布局、iPad 自适应（SwiftUI 响应式）。

### 数据模型
- `Alarm`：id、time（时刻）、repeats（周几）、label、enabled、ringtoneID。
- `Timer`：时长（秒）、label。
- `Ringtone`：id、name、类型（内置音乐 / 自定义混音）、文件URL、musicVolume、voiceVolume。
- `VoiceRecording`：录音的临时文件。

### 核心实现模块
1. **通知闹钟**：`UNUserNotificationCenter` 调度每日/定时本地通知；通知的自定义声音从 App 沙盒铃声文件（AVAudioFile 导出）获取。定时器用 `UNTimeIntervalNotificationTrigger`。可重复闹钟用 `UNCalendarNotificationTrigger`。
2. **铃声库与内置音乐**：内置音乐作为 Bundle 资源随 App 打包；自定义混音铃声导出到沙盒 Library。
3. **录音**：`AVAudioRecorder`（m4a），录音时长上限（如 60s）。
4. **混音**：`AVAudioEngine` 或 `AVAudioMixerNode`，把音乐文件与人声文件混到一条输出，导出为铃声文件。
5. **设置项**：默认响铃时长、渐响、重复次数、小睡（贪睡）。

### 平台/设备
- Universal target（iPhone + iPad），SwiftUI，iOS 15+。

## 交付/构建方式
- 本地 Xcode 工程，免费 Apple ID 签名，直接安装到用户 iPhone/iPad。
- 真机验证"锁屏响铃"。

## 留给实现者的决策（What's Left to the Builder）
- 预置音乐片段的具体选择与时长（建议每段 15–30s、循环）。
- 混音导出音频格式与码率。
- 录音 UI 与试听交互细节。
- 具体 Schedule 通知的重复逻辑。

## 关键取舍（Calls made so far）
- 采用原生 SwiftUI（方案 A）。
- 预置铃声为 App 内置，不接入 iTunes 音乐库（规避版权）。
- v1 采用轻方案混音（人声叠音乐 + 音量调节），高级编辑留 v2。
- 免费 Apple ID 签名，接受 7 天重签。
- Xcode 16.2（Intel 机上限）。
